## 2. Korrekte Semantik (verifiziert, im Store belegt)

- RAS-interner Standard: **20 °C** — eine Konstante `config.RAS_BASE_C = 20.0`
  (maintainer 2026-11-02). Nichts mit den 20 °C im UVR-Regler, nichts mit
  Absenkung — beide „kommen später mit rein" (dann wäre das Ziel
  je-Zonen/-zeitabhängig = v2).
- **RAS-Soll (Ziel-Raumtemp) = 20 − Offset** — direkt abgeleitet aus dem
  Store-`offset_{z}` (live; ändert sich mit dem RAS-Drehregler). Keine
  je-Zonen-Konstanten, kein extra Loggen (Q-107: Soll wird nicht als eigener
  Kanal geloggt).
- Der RAS regelt **Perzipiert = Ist + Offset auf 20** → **Ist stabilisiert
  bei 20 − Offset**.
- **Richtung: Offset ↑ → Soll ↓ → Raum kühlt; Offset ↓ → Soll ↑ → wärmer.**
- **Beleg DG** (sauberer Heizkreis; Keller aussortiert wegen
  Trocknungsgerät): Winter 2026 Ø Ist 20,11 @ off −0,1 (n=1360 h) = Soll
  20,1 ✓ · Ø Ist 18,86 @ off +1,1 (n=248 h) = Soll 18,9 ✓ · **live 22:00
  DG Ist 18,6 @ off +1,4 → Soll 18,6, sitzt exakt drauf** (Perzipiert 20,0).
  Alle 3 Zonen live konsistent: Keller +3,5 → 16,5 ✓ · EG −1,7 → 21,7 ✓ ·
  DG +1,4 → 18,6 ✓.

## 3. Design (v0.3-FIX, 2026-11-03): Komfort-Referenz = the maintainer's aktueller Intent

Komfort-Referenz = the maintainer's **aktueller Intent** `soll = RAS_BASE_C − offset_now`
(`recommend.py: ras_soll_now()`) — **fix** für die gesamte
Kandidaten-Bewertung (KEIN Δ). Der Kandidat verschiebt sein eigenes Ziel NUR
über die L1-Dynamik (Perzipiert-Trajektorie); die Messlatte bleibt the maintainer's
Einstellung:

```text
intent[z]      = RAS_BASE_C − offset_now[z]               # ras_soll_now()
ist_cand[z][h] = perz_cand[z][h] − (offset_now[z] + cand_Δ[z])   # comfort_cost()
Komfort  = Σ_z Σ_{h=0..11} max(0, |ist_cand[h] − intent| − COMFORT_BAND_K)²
```

**Warum NICHT das Kandidaten-Ziel (v0.3-Alpha, verworfen):**
`soll_cand = RAS_BASE_C − (off_now + Δ)` war zweierlei falsch:
**(1) zirkulär** — ein Kandidat misst seinen Komfort an seinem EIGENEN Ziel →
jeder eingeregelte Kandidat ist „komfortabel" → die Offset-Wahl läuft über
L1-Transient-Artefakte statt über Raumtemp-vs-Intent;
**(2) h=0-Buchführungs-Artefakt** — `apply_offset_step` verschiebt die
Perzipierte um Δ (`perz_cand[0] = perz_now + Δ`), also misst der h=0-Term
`|perz_now + Δ − 20|`: in einem zu-warmen Raum (Keller, perz 25,2) sieht ein
niedrigerer Offset (Δ<0) im h=0-Term „besser" aus, obwohl der Raum sich
physikalisch NICHT bewegt hat. **Live-Beleg (reeller Store, 22:00):** Keller
20,5 °C @ Intent 16,5 (+4,0 zu warm) → Alpha-Logik: +3,5 → +2,5 K
(Soll RAUF = **wärmer**) = der ursprüngliche Bug lebt.

**h=0-Identität (FIX):** `ist_cand[0] = perz_now + Δ − (off_now + Δ)
= ist_now` → Abweichung `|ist_now − intent|` ist für **alle** Δ identisch
(korrekt: nichts ist passiert).

**Invarianz (korrigiert, ersetzt die Alpha-Invarianz):** Die Abweichung misst
die **reale Raumtemperatur gegen den fixen Intent**; Kandidatenabhängigkeit
**NUR** über das L1-Perzipiert-Transient (gewollt: L1 kennt die
Hausdynamik, die Metrik den Intent) + h=0-Identität. Folge je Situation:
Gleichgewicht (perz = 20, Δ in Band 0,5) → Komfort 0 für alle Δ,
Change-Kosten 0,25 > No-change-Schwelle 0,15 → **No-Change**. Zu warm
(perz-haltend > Intent) → Δ<0 (wärmer) bewegt den Raum VOM Intent weg → nie
günstiger; Δ>0 (kühler) oder No-Change gewinnt. Zu kalt (perz-haltend
< Intent) → bester Δ ≤ 0 (Soll runter = mehr Heizung).

`ist_cand` ist die exakte Inverse von `m2b.features.apply_offset_step`
(m2b bleibt anfangsfrei). Band `COMFORT_BAND_K = 0,5` unverändert; der
`rt_soll_at`-Pfad (Bau im Hauptlauf + Import `rt_soll`) entfällt.

**Empfehlungstext (v0.3, DoD-4):** `„Ist {ist:.1f} °C (Soll {soll:.1f} °C,
Abw. {dev:+.1f} K) …"` mit `ist` aus `state.rows[ras_{z}_ist]`,
`soll = RAS_BASE_C − off_now`, Abweichung **vorzeichungsgetreu**
(+ = zu warm). Das alte Format „Perzipiert … (Soll 20 °C, Abw. …)" entfällt
(alle L2-Texte, inkl. Tier-A-Advice + Stale-Pfad-semantik unverändert).

## 6. Effektor-Guard (Minderer-3-h-Fenster, Fix-2)

**Problem (maintainer 2026-11-03):** Keller Ist 20,5 > Intent 16,5 (zu warm durch
**externes Trocknungsgerät**). Der Heizkreis Keller ist **aus** (Rücklaufminderer
zu, perzipiert 24–25 °C > 20,1 °C-Schwelle). Der RAS kann heizen, aber
**nicht kühlen** → der Offset hat **keine Stellkraft**: höherer Offset (kühler)
kühlt nichts zusätzlich (Raum kühlt nur von selbst), niedrigerer (wärmer) ist
die falsche Richtung. „Offset ändern" wäre **bloß** (keine Wirkung auf
Temperatur/Ölverbrauch).

### 6.1 Signal-Definition (Store-Beleg m1.3, 2026-11-03)

`hzrkl_{z}_rule` = Rücklaufminderer-Offen-Anteil der Stunde t je Zone
(`m1`-`rule_state()`: **1 = offen** (perzipiert < 20,1 °C, Kreis KANN heizen),
**0 = zu** (perzipiert > 20,1, Kreis aus); reale Werte sind Stunden-
Offen-Anteile, z. B. 0,39/0,52 = Flapping am Schwellwert). `hzrkl_{z}_rule_lag1`
= t−1 h, `hzrkl_{z}_rule_lag2` = t−2 h → **3-h-Fenster aus EINER Store-Zeile**
(kein extra Ladepfad). `minderer_state(rows, zone)` = 3-h-Ø(open) aus
`rule`/`lag1`/`lag2` + Status:

- `≤ MINDERER_CLOSED_MAX` (0,1) = **„zu"** — seit ~3 h zu. Mathematisch:
  „seit 3 h zu" ⇒ perzipiert ≥ 20,1 ⇒ Ist ≥ Intent + 0,1 (immer wärmer als
  Intent) → die „zu-warm"-Bedingung ist implizit erfüllt.
- `≥ MINDERER_OPEN_MIN` (0,9) = **„offen"** — normal/regelt.
- dazwischen = **„flapping"** — periodische Aktivierung am Schwellwert.
- NULL/fehlend in JEDER der 3 Stunden = **„unbekannt"** → Guard stumm
  (Fail-Open: Empfehlungskandidaten unverändert, kein Text). Dokumentiert:
  ältere Store-Monate ohne m1.3-Regelspalten liefern NULL → der Guard darf
  keine Empfehlung unterdrücken, die er nicht belegen kann.
