„Vorlauftemperatur so niedrig wie möglich — nur solange mindestens einer der
drei Heizkreise Wärme braucht.“ ΔT-Kriterium (VL − Strang-RL) ≈ 10 K:
**kleinerer** ΔT = Wasser fließt zu schnell → Minderer drosseln. maintainer,

durchflussabhängig** → direkter 1-h-Vergleich passt selten → Lag-Schätzung auf

## 2. Architektur (einmalig vs. pro-Call) — bewusst getrennt

| Schicht | Wann | Aufwand |

| **Lag-Schätzung** `estimate_lags()` (CLI `python -m analysis.model.l2 estimate-lags`) | **einmalig**, caches-fähig | Kreuzkorrelation über bis zu 30 Tage 10-s-Rohdaten (~1–2 s) → `data/l2/rm_lag_estimate.json` |

## 3. Lag-Schätzungs-Methodik

1. **Daten:** 10-s-Rohdaten `data/winsol_pq` + `data/cmi_log_pq`
   (Hive `YYYY/MM/YYYY-MM.parquet`, 71 Spalten; `ts` VARCHAR ISO).
   Kanäle (verifiziert 2026-11-07, s. `l2.config.RM_RAW_*`):
   - VL (Vorlauf Heizkreis) = `dev0_analog_06` (dev0 a6)
   - zentraler RL = `dev0_analog_07` (dev0 a7)
   - Strang-RL je Etage (UVR610 „HzRk Ventil 1“ PT1000):
     Keller = `dev2_analog_13` (rlK), **DG = `dev2_analog_14` (rlDg)**,
     **EG = `dev2_analog_15` (rlEg)** — Zuordnung = `ui/js/state-map.js`
     (2026-11-06, `preferJson`; transparent in `config.RM_RAW_STRANG_RL`).
   - Minderer-Vorgabe (befohlen, 0–10 V, „HzRk Ventil 2“; **befohlene** Werte,
     keine Positionssensoren, F8): Keller = `dev2_analog_10`,
     EG = `dev2_analog_11`, **OG/DG = `dev2_analog_12`**.
   - Pumpe Heizkreis O8 = `dev0_digital_08`.
2. **Grid:** Rohdaten auf ein äquidistantes 10-s-Raster (hold-last,
   `searchsorted`) → `RL[t+L]` ist zeitlich exakt L Sekunden später (VL führt,
   RL folgt).
3. **Aktive Maske (Durchfluss-Klasse „offen“):** `Pumpe an (d8 > 0,5)` AND
   `Minderer-offen (a > 5 V, 0–10 V → 0–1)`. Keller-Kreis läuft kaum
   (Trocknungsgerät) → n klein → **Default-Lag-Fallback**
   (`RM_LAG_MIN_SAMPLES = 500`).
4. **Kreuzkorrelation:** `corr(VL[t], RL[t+L])` für `L = 0…3600 s`
   (Schritt 10 s); Bestwert = max. Korrelation; **striktes `>`** → bei Ties
   das kleinste L (deterministisch). Min. Stdabweichung 0,3 °C je Serie
   (flaches Signal → ungültig), min. 100 Überlappungssamples.
5. **Konfidenz (heuristisch, 0–1):**
   `0,5·|corr| + 0,25·min(n/40 000, 1) + 0,25·max(Schärfe, 0)` —
   Schärfe = Peak − Ø der ±2-Schritt-Nachbarn in der Lag-Kurve.
   (Kein RNG; reine Daten-Größe + Peak-Eindeutigkeit.)

## 4. ΔT je Etage (mit Lag-Korrektur)

`ΔT(z) = VL(lag-korrigiert) − Strang-RL(z, jetzt)`; VL führt, RL folgt →
`RL` um `Lag_z` nach vorn verschieben (10-s-Roh-Fenster, 2 h, Ø).
**Fallback** (Rohdaten nicht lesbar): stündlicher Store-2-h-Ø
(`hz_vl`−`hzrkl_{z}_pos` + `hz_vl_lag1`−`hzrkl_{z}_pos_last`; sub-stündlicher
Lag ist im Stunden-Ø inhärent gemittelt → keine explizite Versetzung möglich).
`delta_t_gap_c = RM_DELTA_T_TARGET_C − ΔT` (> 0 = ΔT zu klein = „Fluss zu
schnell“, maintainer-Kriterium).

### ΔT-Beleg gegen Referenz (547-h-Fenster 15.10.–07.11., mild)

Methodik (stündliche Ø-ΔT je Minderer-offen-Klasse, Lag-korrigiert)
**reproduziert die Referenz-Beleg-Zahl** (Beleg 2026-11-07):

| DG offen | **6,3 K** (n=139) | ≈ 6,3 K |

→ 10-K-Kriterium heute **nicht** erfüllt (EG dauerhaft ~4 K = „zu schneller

ist dann kein Fluss-Kennwert).

## 5. Konditions-Flag „≥ 1 Kreis braucht Wärme“

`active = (Pumpen-3-h-Ø ≥ 0,5) OR (Minderer-offen-2-h-Ø ≥ 0,5 in ≥ 1 Etage)
OR (RAS-perzipiert < Intent − 0,5 K in ≥ 1 Zone)` (Intent =
`RAS_BASE_C − offset`, `RAS_BASE_C = 20 °C`). Alle Signale aus **einer**
Store-Zeile (`pump_hz_on_sum3h`, `hzrkl_{z}_on` + `_lag1`, `ras_{z}_perc` +
`offset_{z}`) — wie `minderer_state`/`heating_active`, kein extra Ladepfad.
NULL-Fail-Open (fehlende Spalte → kein Beitrag).

**Inaktiv → Block stumm** (maintainer-Bedingung: „VL niedrig“ ist sonst nicht
definiert): `rm_diagnostics.per_zone = {}`, keine ΔT-Lage; Flag + Grund
bleiben sichtbar. (Tickets A/B/C/UI konsumieren das Flag als Gate.)
